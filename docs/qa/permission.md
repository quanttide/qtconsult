# 权限 QA

> 当前平台尚无账号系统，以下用例描述的是权限机制上线后的预期行为，供后续实现参考。

## 角色定义

| 角色 | 范围 | 典型用户 |
|:-----|:-----|:---------|
| 顾问 | 所有工作区 | 量潮内部咨询团队 |
| 合作者 | 参与的工作区 | 外部专家、联合交付方 |
| 客户 | 自己的工作区 | 购买咨询服务的客户 |

## TC-PM-001 顾问查看所有工作区

| 项目 | 内容 |
|:-----|:-----|
| 前置条件 | 以顾问身份登录，系统有多个工作区 |
| 操作步骤 | 打开应用，查看工作区列表 |
| 预期结果 | 列出所有工作区，包括客户的和合作的 |

## TC-PM-002 客户只能看到自己的工作区

| 项目 | 内容 |
|:-----|:-----|
| 前置条件 | 以客户身份登录，系统有多个工作区但客户只属于其中一个 |
| 操作步骤 | 打开应用，查看工作区列表 |
| 预期结果 | 1. 列表只显示客户所属的工作区<br>2. 看不到其他客户的工作区<br>3. 看不到工作区列表里出现不属于自己的项目 |

## TC-PM-003 客户不能访问其他工作区

| 项目 | 内容 |
|:-----|:-----|
| 前置条件 | 以客户身份登录，知道其他工作区的 URL 或项目 ID |
| 操作步骤 | 尝试直接访问不属于自己的工作区或项目 |
| 预期结果 | 1. 页面返回无权限提示或 404<br>2. 不会泄露其他工作区的任何数据 |

## TC-PM-004 合作者看到参与的工作区

| 项目 | 内容 |
|:-----|:-----|
| 前置条件 | 以合作者身份登录，参与部分工作区 |
| 操作步骤 | 打开应用，查看工作区列表 |
| 预期结果 | 1. 列表只显示合作者被授权参与的工作区<br>2. 未参与的工作区不出现 |

## TC-PM-005 客户无法修改系统配置

| 项目 | 内容 |
|:-----|:-----|
| 前置条件 | 以客户身份登录，进入自己的工作区 |
| 操作步骤 | 尝试进行工作区级别的管理操作（修改工作区信息、管理项目成员等） |
| 预期结果 | 客户只能操作看板内的卡片，无法执行管理操作 |

## TC-PM-006 未登录用户无法使用

| 项目 | 内容 |
|:-----|:-----|
| 前置条件 | 未登录或 token 无效 |
| 操作步骤 | 打开应用或调用 API |
| 预期结果 | 1. 应用提示登录或认证失败<br>2. 不展示任何业务数据<br>3. 写操作一律拒绝 |

## 当前实现状态

当前 Provider 仅支持 Bearer token 认证（全局 token 和 scope token），尚无用户体系、角色管理和登录界面。以上用例为后续账号系统上线后的验收标准。
