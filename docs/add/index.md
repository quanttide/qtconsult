# 需求分析文档

## 看板总览

看板是咨询项目的工作空间，按 OODA 循环分为四个列表展示不同类型的信息卡片。

| 列表 | 卡片类型 | 说明 |
|------|----------|------|
| **Observe** | 调研卡 | 记录客户的事实与发现 |
| **Orient** | 洞察卡 | 提炼矛盾、根因与影响 |
| **Decide** | 策略卡 | 制定可执行方案 |
| **Act** | 任务卡 | 追踪落地执行 |

## 卡片

卡片是看板的基本单元。

### 内置字段

| 标识 | 中文 | 类型 | 说明 |
|------|------|------|------|
| title | 标题 | string | 卡片名称 |
| description | 描述 | string | 展开说明 |
| category | 系统分类 | string | 系统内置概念，如 ideal / reality |
| types | 问题领域 | string[] | 问题所属领域，如战略技术断层、数据基建 |
| tags | 标签 | string[] | 灵活标记，支持多标签 |
| date | 日期 | date | 支持单日期和起止日期 |
| assignee | 负责人 | string | 执行人 |
| upstream | 上游卡片 | Card[] | 信息来源引用 |

### 自定义字段

按具体咨询项目动态配置业务字段，如根因、影响、优势、资源需求、客户倾向、进度等。

## 列表与卡片类型

列表中存放对应类型的卡片：

- **Observe 列表** — 存放调研卡，包含两个子列表：
  - **业务理想** — 客户期望达成的目标状态
  - **技术现实** — 当前的实际情况与技术现状
- **Orient 列表** — 存放洞察卡，从调研卡中提炼分析结论，通过"来源卡片"引用调研卡
- **Decide 列表** — 存放策略卡，基于洞察生成方案，通过"来源卡片"引用洞察卡
- **Act 列表** — 存放任务卡，分解策略为执行事项，通过"来源卡片"引用策略卡

卡片之间形成信息链路：

```
调研卡（Observe）→ 洞察卡（Orient）→ 策略卡（Decide）→ 任务卡（Act）
```
