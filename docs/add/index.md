# 领域模型定义

## 看板（Board）

看板是工作空间的基本组织单元，每个项目对应一个看板。看板包含列表和卡片。

## 列表（List）

列表看板的列，对应咨询流程的不同阶段。每个看板固定包含四个列表，按 OODA 循环排列：

| 列表 | 阶段 | 说明 |
|------|------|------|
| **Observe** | 调研 | 收集客户事实与现状 |
| **Orient** | 分析 | 提炼矛盾、根因与影响 |
| **Decide** | 决策 | 制定策略方案 |
| **Act** | 执行 | 追踪任务落地 |

卡片自左向右流转：`Observe → Orient → Decide → Act`。

## 卡片（Card）

卡片是看板的基本单元，即积木块（Block）。卡片的所有信息分为两类：

| 类别 | 说明 | 示例 |
|------|------|------|
| **内置字段** | 系统预置，不可变更 | 标题、描述、创建时间、创建人 |
| **自定义字段** | 按问题动态配置 | 来源、优先级、负责人 |

### 阶段特有字段

卡片在不同的列表阶段拥有不同的内置字段：

#### Observe 阶段

| 字段 | 类型 | 说明 |
|------|------|------|
| 标题 | string | 核心事实概述 |
| 副标题 | string | 补充说明 |
| 描述 | string | 事实展开 |
| 分类 | enum | `业务理想` / `现实状况` |
| 来源 | string | 信息来源 |
| 日期 | date | 记录日期 |
| 确认状态 | enum | `待确认` / `已确认` |

#### Orient 阶段

| 字段 | 类型 | 说明 |
|------|------|------|
| 标题 | string | 洞察结论陈述 |
| 根因 | string | 根本原因分析 |
| 影响 | string | 不处理的后果 |
| 关联卡片 | Card[] | 引用的 Observe 卡片 |
| 聚类标签 | string | 所属分析维度 |

#### Decide 阶段

| 字段 | 类型 | 说明 |
|------|------|------|
| 标题 | string | 方案名称 |
| 优势 | string | 选择理由 |
| 概要 | string | 执行计划 |
| 资源需求 | string | 人时费估算 |
| 关键假设 | string | 前提条件 |
| 客户倾向 | bool | 是否选中 |
| 客户备注 | string | 顾虑或条件 |

#### Act 阶段

| 字段 | 类型 | 说明 |
|------|------|------|
| 标题 | string | 任务描述 |
| 状态 | enum | `待开始` / `进行中` / `已完成` / `受阻` |
| 负责人 | string | 执行人 |
| 开始日期 | date | 计划开始 |
| 截止日期 | date | 计划结束 |
| 进度 | int | 完成百分比 |
| 受阻原因 | string | 受阻时必填 |
| 备注 | string | 补充信息 |
| 关联卡片 | Card | 所属的 Decide 卡片 |

### 卡片流转规则

- 卡片从右向左逐列移动，不可跨列跳转
- Observe 卡片的"确认状态"为"已确认"后才可移至 Orient
- Act 卡片"状态"为"受阻"时必须填写"受阻原因"
- 卡片移回前一列需保留字段历史
- 删除卡片不影响已关联的其他卡片（断开链接）
